### FIX-02 — Защита webhook: убрать секретный URL из кода

**Приоритет:** HIGH  
**Статус:** OPEN  
**Связанная задача из PROTOCOL:** `B12`  
**Файлы:**  
- `retail-audit-calc/scripts/seller_order.py`
- `retail-audit-calc/scripts/buyer_check.py`
- Google Apps Script endpoint
- конфигурация окружения Dify

**Описание проблемы:**  
В коде захардкожен публичный URL Google Apps Script Web App. Это создаёт риск:
- посторонней отправки логов;
- засорения Google Sheets;
- исчерпания лимитов Apps Script;
- подмены данных, если endpoint не проверяет токен.

**Предлагаемое решение:**

1. Убрать webhook URL из исходного кода.
2. Использовать переменные окружения или секреты Dify:
   - `RETAIL_AUDIT_WEBHOOK_URL`
   - `RETAIL_AUDIT_WEBHOOK_TOKEN`
3. Если переменные не заданы:
   - скрипт не падает;
   - логирование тихо пропускается или пишется предупреждение без секрета.
4. На стороне Google Apps Script добавить проверку токена.
5. Перевыпустить / ротацию вебхука, так как старый URL уже мог попасть в историю репозитория.

**Ожидаемый эффект:**  
Только авторизованные запросы смогут писать логи.

**Риски:**  
Если переменные окружения не будут настроены, логирование может временно остановиться.

**Критерий закрытия:**
- в репозитории нет боевого webhook URL;
- токен не хранится в открытом виде;
- запрос без токена или с неверным токеном отклоняется;
- запрос с верным токеном успешно пишет лог;
- тестовые запросы `тест_*` не пишутся.

### FIX-03 — Добавить страховой коэффициент в заказ продавца

**Приоритет:** MEDIUM  
**Статус:** OPEN  
**Файлы:**  
- `retail-audit-calc/scripts/seller_order.py`

**Описание проблемы:**  
В `seller_order.py` расчёт недельного заказа выполняется как продажи за месяц / 4.  
В `buyer_audit.py` используется дополнительный коэффициент страхового запаса.

Это создаёт расхождение:
- продавец получает заказ без страхового запаса;
- закупщик видит расчёт уже со страховым запасом.

**Предлагаемое решение:**  
Ввести единый настраиваемый коэффициент страхового запаса.

Рекомендуемое базовое значение:

```text
1.10
```

То есть:

```text
недельный заказ = (продажи за 30 дней / 4) * 1.10
```

Для гибкости можно добавить аргумент:

```text
--safety-factor
```

**Ожидаемый эффект:**  
Снижение риска дефицита на полке при колебаниях спроса.

**Риски:**  
Возможное увеличение излишков, если коэффициент окажется слишком высоким для отдельных категорий.

**Критерий закрытия:**
- коэффициент применяется ко всем категориям заказов продавца;
- значение можно переопределить через CLI;
- результаты сравниваются с расчётами `buyer_audit.py` без противоречий.

### IMP-03 — Обработка ошибок чтения файлов

**Приоритет:** MEDIUM  
**Статус:** OPEN  
**Файлы:**  
- `run_audit.py`
- `seller_order.py`
- `buyer_check.py`
- `buyer_audit.py`
- `check_catalog.py`
- `repricing.py`

**Описание проблемы:**  
При отсутствии, повреждении файла или отсутствии нужной колонки скрипт может завершаться с traceback вместо понятного сообщения.

Особенно чувствительно:
- отсутствие `sales.xlsx`;
- отсутствие `Количество`;
- отсутствие `Наименование`;
- пустой результат `glob.glob()`;
- повреждённый Excel.

**Предлагаемое решение:**  
Добавить единый подход:
- проверять существование файлов;
- оборачивать чтение в обработку ошибок;
- проверять наличие обязательных колонок;
- выводить сообщения формата:

```text
ERR|Файл продаж не найден: sales.xlsx
ERR|В файле продаж отсутствует колонка Количество
ERR|Файл повреждён или не читается как Excel
```

**Ожидаемый эффект:**  
Пользователь получает понятную причину ошибки, а не Python traceback.

**Риски:**  
Избыточная обработка может скрыть детали, если не логировать причину.

**Критерий закрытия:**
- при отсутствии файла скрипт не падает с traceback;
- при повреждённом файле выводится понятная ошибка;
- при отсутствии обязательной колонки выводится понятная ошибка.

### 7.2. Заказы продавцов

Проверить тестовые запросы:

```bash
python3 main.py order --cat beer --store тест_энгельс
python3 main.py order --cat snacks --store тест_батов
python3 main.py order --cat glass --store тест_возд
python3 main.py order --cat kids --store тест_котельниково
```

Ожидание:
- команды завершаются без ошибок;
- формат вывода соответствует ожидаемым блокам `CP`, `SP`, `GP`, `KP`, `ROT`, `BROT`, `GROT`, `KROT`;

## 8. Критерии полного закрытия аудита

Аудит считается закрытым, если:

1. Исправлен `FIX-01`.
2. Закрыт `FIX-02`:
   - webhook URL убран из кода;
   - добавлен токен;
   - старый endpoint ротацию или защищён.
3. Добавлен страховой коэффициент `FIX-03`.
4. Закрыт `EDGE-01`.
5. Общий код вынесен в `utils.py`.
6. Канонизация SKU унифицирована.
7. Ошибки чтения файлов обрабатываются корректно.
8. Обновлён `PROTOCOL.md`.
9. Прогнан регрессионный чек-лист.
10. Владельцем подтверждено, что тестовые сценарии работают.

## 9. Идеи вне текущего скоупа

Отдельные направления, которые можно рассмотреть позже:

1. **Единый справочник алиасов магазинов**  
   Например: `энгельс`, `энгельса`, `энгельса 1`, `engel` → одно каноническое имя.

2. **Тестовые эталоны названий товаров**  
   Небольшой файл `tests/golden_sku.txt`, где для каждого грязного названия указан ожидаемый канонический результат.

3. **Автоматическое определение периода продаж**  
   Чтобы не полагаться на фиксированные 30 дней, если формат выгрузки из 1С изменится.

4. **Прогнозирование заказов**  
   Учёт дня недели, праздников и сезонности вместо простого деления на 4 недели.

5. **Локальный кэш каталога**  
   Если файлы большие, можно предварительно нормализовать и кэшировать справочники.

6. **Отдельный конфиг для порогов**  
   Пороги балласта, ротации, страховые коэффициенты и минимальные объёмы лучше хранить в одном конфигурационном файле или словаре.
